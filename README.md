# Лабораторна робота №2

Синхронізація паралельних операцій за допомогою механізму подій та механізму майбутніх результатів.

Кожен файл у `src` — окрема програма зі своєю функцією `main`. Їх не можна збирати в один exe: лінкер побачить кілька `main`.

| Пункт | Файл | Що показує |
| --- | --- | --- |
| 1.2.1 | `src/121_data_flag.cpp` | Черга чисел, прапорець, `unique_lock`, `sleep_for(100 мс)` |
| 1.2.2 | `src/122_notify_all.cpp` | Три потоки `Waits` і `notify_all` (спочатку при `i = 0`, потім при `i = 1`) |
| 1.2.3 | `src/123_notify_one.cpp` | Три потоки і один `notify_one` |
| 1.2.4 | `src/124_condition_variable.cpp` | Та сама черга, що в 1.2.1, але через `condition_variable` |
| 1.2.5 | `src/125_async.cpp` | `std::async`: `launch::deferred` і `launch::async` |
| 1.2.6 | `src/126_packaged_task.cpp` | Два деки: завдання `packaged_task` і номери `n` |
| 1.2.7 | `src/127_promise.cpp` | Два потоки типу `void` і пара `promise` / `future` без глобальних змінних |
| — | `src/prime.hpp` | Спільна функція n-го простого числа для пунктів 1.2.5–1.2.7 |
| — | `src/console.hpp` | Кодування консолі Windows UTF-8 |

## Збірка

Потрібен компілятор C++17 з підтримкою потоків. Для MinGW це збірка з POSIX-потоками, не win32-threads.

З каталогу цього репозиторію:

```powershell
g++ -std=c++17 -O2 -pthread src/121_data_flag.cpp -o out/121.exe
g++ -std=c++17 -O2 -pthread src/122_notify_all.cpp -o out/122.exe
g++ -std=c++17 -O2 -pthread src/123_notify_one.cpp -o out/123.exe
g++ -std=c++17 -O2 -pthread src/124_condition_variable.cpp -o out/124.exe
g++ -std=c++17 -O2 -pthread src/125_async.cpp -o out/125.exe
g++ -std=c++17 -O2 -pthread src/126_packaged_task.cpp -o out/126.exe
g++ -std=c++17 -O2 -pthread src/127_promise.cpp -o out/127.exe
```

Або однією командою, якщо `g++` уже є в PATH:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

У Visual Studio кожен `.cpp` відкривають як окремий консольний проєкт або збирають так:

```bat
cl /std:c++17 /EHsc /utf-8 /O2 src\121_data_flag.cpp
```

Готові `.exe` у репозиторій не додають. Вони вже вказані в `.gitignore`.

## Запуск

Пункти 1.2.1 і 1.2.4 читають цілі числа, кожне з нового рядка. Порожній рядок або слово `stop` завершує введення. Після цього програма виводить прості числа з черги.

Пункт 1.2.5 питає номер простого числа, потім пропонує корінь, синус або натуральний логарифм від цього номера. Далі те саме повторюється для другого режиму запуску, і програма друкує, скільки мілісекунд зайняв `get()`.

Пункт 1.2.6 приймає кілька номерів до `stop`. Пункт 1.2.7 питає один номер: головний потік друкує n-те і (n·10)-те прості, другий потік після сигналу чекає дві секунди і друкує корінь з n.

Пункти 1.2.2 і 1.2.3 треба запустити кілька разів. У 1.2.2 повідомлення про кінець очікування з’являються лише після другого `notify_all`. У 1.2.3 друкується повідомлення лише з одного потоку, і його номер від запуску до запуску змінюється.
